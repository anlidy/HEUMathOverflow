## 通用规范

### 请求格式

- **Content-Type**: `application/json`（除文件上传接口使用 `multipart/form-data`）
- **认证方式**: 通过Cookie中的sessionID进行认证
- **请求体**: JSON格式，包含必要的参数

### 响应格式

所有API响应都遵循统一的格式：

```typescript
interface ApiResponse<T> {
  code: number;         // 状态码
  message: string;      // 响应消息
  data: T;             // 响应数据
}
```

### 状态码说明

| 状态码 | 说明               |
| ------ | ------------------ |
| 200    | 成功               |
| 400    | 请求参数错误       |
| 401    | 未授权，需要登录   |
| 403    | 禁止访问，权限不足 |
| 404    | 资源不存在         |
| 409    | 冲突，如重复操作   |
| 422    | 参数验证失败       |
| 429    | 请求频率限制       |
| 500    | 服务器内部错误     |
| 502    | 外部服务不可用     |
| 503    | 服务超时           |

### 分页规范

所有列表接口都支持分页，分页参数和响应格式统一：

**请求参数**:

- `page`: 页码，从1开始，默认1
- `limit`: 每页数量，默认20

**响应格式**:

```typescript
interface PaginationResponse<T> {
  items: T[];           // 数据列表
  pagination: {
    page: number;       // 当前页码
    limit: number;      // 每页数量
    total: number;      // 总数量
    totalPages: number; // 总页数
  }
}
```

### 时间格式

所有时间字段都使用ISO 8601格式：`YYYY-MM-DDTHH:mm:ss.sssZ`

### 文件上传

文件上传接口使用 `multipart/form-data` 格式，支持的文件类型：

- 文档：PDF, DOC, DOCX, TXT
- 图片：JPG, JPEG, PNG, GIF
- 文件大小限制：根据具体接口而定

## 开发指南

### 1. 接口调用顺序

1. 用户注册/登录获取session
2. 根据用户角色调用相应的功能接口
3. 使用session进行后续API调用

### 2. 错误处理

- 检查响应中的 `code` 字段判断请求是否成功
- 根据 `message` 字段获取错误详情
- 401错误需要重新登录
- 403错误需要检查用户权限

### 3. 权限说明

- **学生**: 可以发帖、回复、点赞、收藏
- **教师**: 拥有学生权限 + 认证答案、审核内容
- **管理员**: 拥有所有权限 + 系统管理

### 4. 开发注意事项

- 所有接口都需要进行参数验证
- 文件上传需要检查文件类型和大小
- 敏感操作需要二次确认
- 大量数据操作建议使用分页
- 实时功能建议使用WebSocket（后续扩展）
